---
title: 更新するとき
description: Queruneを新しい版へ更新するときに必要な手順。
---

## `ALLOWED_EMAILS`を使っていた場合の更新

以前のQueruneは、`ALLOWED_EMAILS`に一致する人を初回ログインで自動的に作っていました。いまは`ALLOWED_EMAILS`を使わず、一覧にいる人は全員ログインできます。更新するときは次の手順に従ってください。

1. 更新する前に、管理画面のユーザー一覧を確認します。
2. ログインさせたくない人を削除します。対象は`ALLOWED_EMAILS`のドメイン指定や`*`で自動的に作られた人と、`ALLOWED_EMAILS`から外してログインを止めていた人です。削除するとセッションとMCPの接続も切れます。
3. 更新します。
4. `ALLOWED_EMAILS`の設定を消します。残っていても使われず、エラーにもなりません。

## パスワードのハッシュがscryptになる版へ更新するとき

既存のユーザーのパスワードはPBKDF2のまま使えます。更新後に新しく設定したパスワードと、登録されていないメールアドレスでのログインの確認はscryptになります。既存のユーザーがいる間は、ログインの応答時間から登録済みのメールアドレスが分かることがあります。避けたい場合は、更新の前に`PASSWORD_HASH_ALGORITHM`を`pbkdf2`にしてください。このとき`PASSWORD_PBKDF2_ITERATIONS`は設定せず、既定の100000のままにしてください。既存のハッシュは100000回で作られているので、回数を変えると応答時間の差がまた生じます。OIDC方式ではパスワードのハッシュを使わないので関係ありません。

## `ga4_pages`を追加したデプロイの後

1. デプロイ後に取り込み状況の画面を開きます。
2. GA4のプロパティがあるサイトごとに、直近14日以上（推奨は直近90日）を「期間を選んで取り込む」で取り込みます。

`ga4_pages`の直近14日が埋まると、`GET /api/v1/sites/:id/sync`と`get_sync_status`のサイト全体の`final_through`が戻ります。それまではサイト全体の`final_through`が`null`になることがあります。手動で取り込まなくても、最初の18:00 UTCの毎日の取り込みで直近10日は入ります。期間の取り込みは全データセットを取り直すため、そのぶんメッセージとD1の書き込み行数が増えます。
